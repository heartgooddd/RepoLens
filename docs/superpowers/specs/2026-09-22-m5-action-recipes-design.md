# M5 已登记操作配方设计

日期：2026-09-22

状态：已按用户批准方案实施并验收；沿用 M3 真实实跑依据，本轮未发起付费模型请求。

目标分支：`feat/m5-action-recipes`

## 1. 目标与边界

M5 将 M3 已真实验证的 PocketFlow 教程生成入口登记为第一份正式运行配方。页面不再手写这项操作的表单，而是读取配方描述生成参数表单；后台只运行代码中登记并固定版本的入口。

被分析的仓库快照始终是输入数据，不是执行代码。浏览器上传文件和 GitHub 导入快照都不能提供命令、解释器、工作目录或入口文件。M5 只声明 PocketFlow 配方获得真实支持；隔离运行测试夹具只证明运行器行为，不代表新增第三方项目已经接入。

本阶段不重新发起付费模型请求。PocketFlow 的真实可用性沿用 `evidence/m3/acceptance.md` 的实跑证据；M5 验证登记、动态表单、隔离、停止、超时、退出码和产物边界。

## 2. 选择的方案

采用代码登记的配方注册表和 macOS `sandbox-exec` 隔离执行。

未选择用户可编辑 YAML 或命令模板，因为它会把配置文件变成新的任意执行入口。未选择 Docker，因为当前产品是轻量本机应用，强制引入守护进程和镜像生命周期会扩大 M5 的安装与运维范围。未选择仅依赖 cwd、环境变量和文件权限的软隔离，因为它不能验证目标进程无法读取主机其他文件。

真实配方在非 macOS、缺少 `sandbox-exec` 或隔离能力自检失败时拒绝启动，不静默降级。

## 3. 配方模型与注册表

新增 `server/app/recipes/`，包含不可由请求修改的注册表和 PocketFlow 配方。正式 API 只返回已登记配方的安全描述。

每份配方必须定义：

- 稳定 ID、版本、名称、说明和支持状态；
- 固定解释器与入口、入口来源 Commit、依赖环境及就绪检查；
- 参数名、类型、默认值、枚举或数值范围，以及如何映射成参数数组；
- 输入快照兼容规则和只读挂载位置；
- 固定工作目录策略；
- 默认和最大超时；
- 停止信号、宽限时间和强制终止整个进程组的策略；
- 可登记产物的相对路径、类型、数量和大小限制；
- 需要开放的网络能力与文件访问范围。

第一份正式配方为 `pocketflow-tutorial@1`。它引用 M3 已固定的 PocketFlow Commit、隔离虚拟环境和 worker，支持 `scope`、`language`、`topics` 等经过约束的参数。所有命令均由配方生成参数数组；请求不得提交 command、executable、cwd 或环境变量。

测试可向应用注入独立的夹具注册表，但夹具不进入正式 `GET /api/recipes` 响应、不写入产品文档的支持清单，也不作为第三方项目真实支持证据。

## 4. API、持久化与兼容性

新增 `GET /api/recipes`，返回配方 ID、版本、展示信息、参数模式、依赖状态、超时、停止方式、产物说明和隔离状态。响应不包含主机绝对路径、密钥、完整环境变量或可编辑命令。

`POST /api/runs` 的新请求形态为：

```json
{
  "recipe_id": "pocketflow-tutorial",
  "snapshot_id": "uuid",
  "parameters": {
    "scope": "utils",
    "language": "zh",
    "topics": 3
  }
}
```

后台先查询配方，再以配方模式校验参数和快照兼容性，生成不可变执行计划。未知配方、额外参数、错误类型、越界值、未登记入口和不支持的输入均在创建进程前失败。

迁移 006 为运行记录增加 `recipe_id`、`recipe_version`、规范化参数 JSON 和隔离方式。既有 M3 记录按原字段继续可读，并标记为旧版固定 PocketFlow/替身记录；不会被误认为新的配方执行。结果缓存键加入配方 ID 和版本，配方升级后不复用旧结果。

## 5. 隔离执行与数据流

一次运行按以下顺序进行：

1. 前端读取配方并生成表单。
2. 用户提交配方 ID、快照 ID 和结构化参数。
3. 后台从注册表解析配方，检查运行时和输入兼容性。
4. 后台校验快照哈希，把输入复制到本次运行目录并设为只读。
5. 隔离模块生成一次性 `sandbox-exec` 策略：默认拒绝；仅允许读取系统运行所需路径、固定配方入口、固定依赖环境和本次输入；仅允许写本次运行目录。PocketFlow 配方允许必要的模型网络连接。
6. 监督进程在独立进程组内启动隔离命令，使用受限环境变量和固定 cwd。模型密钥继续通过现有 stdin 通道交给 worker，不进入参数、日志或数据库。
7. 后台流式保存受限日志，记录状态、阶段、退出码和结束原因。
8. 成功后只从本次输出根目录收集配方声明的产物，逐项拒绝链接、路径越界、类型不符、数量或大小超限；最后以事务登记成功状态和产物。

取消时先向整个进程组发送终止信号，等待配方声明的宽限时间，再强制杀死仍存活的进程组。超时走同一停止路径并记录明确的 timeout 错误；非零退出码保留原始数值且不登记成功产物。API 进程异常退出时继续沿用父进程监督器，避免遗留子进程。

## 6. 前端交互

真实项目工作台加载当前可用配方，并从参数模式生成文本、枚举和整数控件。首版只展示 PocketFlow 教程生成配方。

运行面板显示：配方名称与版本、真实验证状态、固定入口来源、依赖是否就绪、隔离方式、默认超时、当前输入快照、参数、进度、日志、停止按钮、退出码和产物位置。依赖、密钥、隔离能力或输入兼容性不满足时禁用启动，并给出可操作原因。

历史运行按记录中的配方版本和参数渲染，不受当前表单修改影响。明确标注测试夹具结果，不把它呈现为正式配方或真实第三方支持。

## 7. 错误处理

新增或规范化以下错误：

- `recipe_not_found`：配方未登记；
- `recipe_parameter_invalid`：参数缺失、额外、类型错误或越界；
- `recipe_input_unsupported`：快照不符合配方当前支持范围；
- `recipe_runtime_unavailable`：固定入口或依赖检查失败；
- `isolation_unavailable`：平台或 `sandbox-exec` 自检失败；
- `recipe_timeout`：超过配方时限并完成进程组清理；
- `recipe_exit_nonzero`：进程非零退出，保留退出码；
- `artifact_policy_violation`：产物路径、类型、链接、数量或大小不合法。

失败、取消、超时和异常退出都不能登记成功产物，也不能被结果缓存命中。

## 8. 测试与验收

实现采用测试驱动，至少覆盖：

- 正式注册表只有 PocketFlow 配方，字段完整，固定 Commit 与 M3 一致；
- API 拒绝未知配方、命令注入、额外/错误参数和未登记执行入口；
- 上传或 GitHub 快照只作为输入，不能改变入口、cwd、依赖或环境；
- 结果缓存按快照、配方版本、模型和全部参数隔离；
- macOS 沙箱夹具能读取允许的输入和写入允许的输出，但不能读取或写入测试创建的范围外文件；
- 停止会清理由夹具创建的子进程，超时不会遗留进程；
- 零退出、非零退出、取消、超时分别记录正确终态与退出码；
- 越界、链接和未声明产物不被登记；
- 前端根据服务端模式生成 PocketFlow 表单，展示依赖/隔离状态、运行进度、退出码与产物；桌面和窄屏均可操作；
- 现有项目、快照、历史运行和 M4 导入路径不回退。

验收记录写入 `evidence/m5/acceptance.md`，明确区分：M3 的真实 PocketFlow 运行证据、M5 的正式配方登记证据，以及仅用于证明隔离运行器行为的夹具证据。本阶段不以夹具声称任何新增第三方项目可用。

## 9. 新增配方的开发流程

新增真实配方必须先明确目标项目、许可证、固定来源版本、真实入口和最小支持参数；再建立独立运行环境并完成人工入口审查。开发者随后：

1. 实现配方定义、参数校验、执行计划和产物策略；
2. 增加隔离访问、停止、超时、退出码和产物测试；
3. 用夹具证明通用运行器行为；
4. 单独执行一次经过授权的真实目标项目验收；
5. 只有真实验收通过后，才把该配方加入正式注册表和支持清单。

完整命令、文件模板和检查清单将在 M5 实现文档中给出。
